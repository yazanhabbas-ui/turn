# Security review

Milestone 8, part 2 (decision D57). Reviewed on 2026-10-01 against the code of that day: every route under `src/app/api`, `src/server/**`, `server.ts`, `src/middleware.ts`, `next.config.ts`, the Docker files (review only), the dependency tree. Method: reading the code, an automated route inventory, more than 300 new tests, a development and a production build driven by a real browser (every page, console watched for policy violations), `npm audit`.

Severity is the impact if exploited in a normal deployment (an office LAN, optionally behind a TLS proxy): **High** = another branch's data or full takeover, **Medium** = a real weakness needing some access or luck, **Low** = hardening or small leak, **Info** = noted. Status: **fixed** (code changed, test added), **accepted** (conscious trade-off, reason given), **documented** (operator action or known limit).

### Checked and found sound

- **SQL:** every query is Drizzle or a `sql` template that binds values as parameters (55 raw templates read; the only `sql.raw` is the test/seed truncate with table names from `pg_tables`). `LIKE` input is escaped.
- **XSS:** no `dangerouslySetInnerHTML`, `innerHTML`, `eval` or `document.write` anywhere; React escapes output; the e-mail HTML escapes the text; ticket printing renders React DOM; user text never goes into an `href` except `tel:` of a stored phone.
- **CSV/Excel:** `guardFormula` prefixes `=`, `+`, `-`, `@`, tab and CR; the same writer serves the report export, the scheduled e-mails, the agent report and the privacy export; Excel cells holding such text are plain strings, never formulas (tested). There is no notification-log export.
- **SSRF:** the server never fetches a URL a user typed. Outgoing requests go to environment-configured endpoints only (`SMS_URL`, `WHATSAPP_API_URL`, SMTP), with a timeout; placeholders in `SMS_URL` are URL-encoded.
- **Open redirect:** `?next=` goes through `safeNext` (relative paths only; `//host`, `/\host`, absolute and `javascript:` fall back to `/`). Tested.
- **Uploads:** pictures are decoded and re-encoded with `sharp` (real type sniffed, not the extension or declared type; png/jpeg/webp and a still gif for the logo; **no svg**; pixel limit against decompression bombs; EXIF dropped; animated images refused), then stored in the database. Served with `nosniff` and a fixed content type.
- **Path traversal:** the server reads files only at fixed paths (`public/audio/ar/<catalog id>`, from a catalog shipped with the code); no request value reaches the file system.
- **Header injection:** download file names are generated ASCII; nodemailer rejects line breaks in headers; no user value is written to a response header.
- **Passwords and tokens:** argon2id (OWASP parameters), constant-time dummy verification for unknown users, password policy on every path that sets a password, session ids are SHA-256 of a 160-bit random token, 12 h sliding expiry, a new token on every sign-in, `HttpOnly`, `SameSite=Lax`, `Secure` over https.
- **CSRF:** every cookie-authenticated mutation needs an `Origin`/`Referer` of this host or `APP_URL` (and a cross-site `Sec-Fetch-Site` is refused); no mutation uses GET.
- **Devices:** the device token is 256 random bits, only its SHA-256 is stored, revocation clears it and disconnects the socket at once, a screen token and a kiosk token open only their own kind of door (tested), a screen socket joins only its own branch's screen room and has no way to join staff rooms (tested).
- **Errors:** an unexpected error returns `{ "error": { "code": "server_error" } }` and is logged server-side; production error pages show no stack.
- **Business rules:** nothing in the application blocks issuing or calling by time of day (D29, D30); this review added no such restriction.

## Residual risks

1. Anyone who can read the database can read visitor data and can see which accounts have 2FA; only 2FA secrets are encrypted at rest. Use disk encryption and database access control; backups can be encrypted by the backup scripts (D58).
2. The demo accounts and password are public. `SEED_DEMO=false` and the first-administrator bootstrap (D58) are the way to a real installation.
3. A compromised administrator account can read everything it is entitled to, send reports to any address (`reports.schedule`) and send a test message to any number (`settings.manage`, 10 a minute). All of it is audited.
4. Page copies in the service worker survive a session that expired without sign-out.
5. The visitor token in a link or QR code is a bearer secret: whoever has the ticket can see its status and rate the visit.
6. Single node: no shared rate-limit store.
